## 3. 진짜 버그 셋

### 3.1 발행이 전부 초안으로 저장됐다

`/write` 에서 발행을 눌러도 아무 일도 일어나지 않았다. DB 를 보면 모든 행이
`draft` 였다.

Network 탭의 **303** 이 결정적이었다 — 서버 액션은 끝까지 돌았다는 뜻이다.

```js
const status = String(form.get('status') ?? 'draft');
...
redirect(status === 'published' ? `/p/${postId}` : `/write/${postId}`);
```

`status` 가 서버에 도착하지 않아 `'draft'` 로 떨어졌다. 그래서

- 저장은 초안으로 되고
- 리다이렉트는 **이미 주소창에 있던** `/write/<id>` 로 갔다

→ 화면상 아무 일도 안 일어난 것처럼 보였다. 두 증상이 한 원인이었다.

`status` 는 제출 버튼의 `name`/`value` 로만 실려 있었는데, `useActionState` 로
만든 액션에서 submitter 의 값이 FormData 에 들어오지 않았다.

**고친 방법:** React 내부 동작을 단정하는 대신 그 의존을 없앴다. 폼에 hidden
`status` 칸을 두고 버튼의 `onClick` 이 값을 적는다. `onClick` 은 submit 보다
먼저 돌므로 순서가 보장된다.

### 3.2 자동저장이 만든 초안과 발행이 서로를 몰랐다

자동저장이 초안을 만들면 그 id 는 `useAutosave` 안에만 남고, 페이지는 여전히
"새 글" 이라 `post` 는 `undefined` 였다.

```jsx
{post && <input type="hidden" name="id" value={post.id} />}   // 늘 렌더되지 않음
```

그래서 발행이 그 초안을 발행하는 대신 **행을 하나 더 INSERT** 했다.
`/me` 에 중복 초안이 쌓인 원인이다. `postId` 를 훅에서 받아 폼에 심었다.

### 3.3 test:rls 가 실패하면 계정을 흘렸다

실제 프로젝트의 `auth.users` 에 `rls-a-*@example.test` 계정 셋이 남아 있었다.
계정 생성이 `try` 블록 **바깥**이라, `makeUser('a')` 가 auth 계정을 만든 뒤
profile insert 에서 던지면 정리 코드에 닿지 못했다.

셋 다 `rls-a-` 인 것이 원인을 그대로 말해 준다.

만든 id 를 즉시 목록에 적고, 생성을 `try` 안으로 옮기고, 시작할 때 앞선
실행이 흘린 계정을 먼저 치우게 했다.

"지금 도는 코드" 로 취급했다.

> [!warning] 재사용할 교훈

> 먼저 확인한다.** Vercel Deployments 탭의 Production 뱃지 하나면 끝날 일이었다.
> 오늘 헤맨 시간의 대부분이 여기서 나왔다.

가설 2 를 스스로 뒤집은 과정도 기록해 둘 만하다. "`1490d94` 는 성공했는데?"

## 5. 그 밖에 잡은 것

**`NOTION_DATABASE_ID` 가 틀려 있었다.** 문서에 data source ID
(`ba421ea0-…`) 를 적어 두었는데, `lib/notion.ts` 는 노션 API `2022-06-28` 로
`POST /v1/databases/{id}/query` 를 부르고 이 엔드포인트는 **database ID**
(`eef19f7daa4c4248ae21c0718e65b41b`) 를 받는다.

하필 나쁜 실수였다 — 잘못된 ID 를 넣으면 통합 연결을 제대로 해 두어도 404 가
나고, **통합 연결을 빼먹었을 때와 증상이 같다.**

**`regions: ["icn1"]` 이 M2-4 에서 사라져 있었다.** Supabase 가 서울인데 리전
고정이 풀리면 질의마다 대륙을 왕복한다. 되돌렸다.

**빌드가 Supabase 에 매달려 있었다.** 홈·카테고리 다섯·`feed.xml` 이 빌드
시점에 미리 렌더되고 그 렌더가 전부 Supabase 를 읽는다. `Gateway Timeout`
하나에 배포가 통째로 죽었다. `lib/retry.ts` 로 300ms·900ms 두 번 더 시도한다.
타임아웃 같은 일시적 실패만 재시도하고, 권한 오류처럼 다시 해도 같은 답이
나올 실패는 즉시 던진다.
